RAG-MCP Pipeline — Architecture Diagram

A visual overview of the Retrieval-Augmented Generation pipeline integrated with an MCP (Model Context Protocol) server and session-based memory stored in FAISS.

Legend
  • FastAPI — receives requests, decodes JWT, and stores per-session messages into FAISS.
  • RAG Pipeline — embeds the query, retrieves context from FAISS, optionally calls an MCP tool, builds prompt context, and calls the LLM to generate an answer.
  • MCP Server — external JSON-RPC server (ISE) providing market data tools at /jsonrpc.
  • FAISS Vector Store — stores both corpus documents and per-user session messages as vectors for retrieval.
Notes & recommendations
  1. Use a dedicated JWT secret (e.g., JWT_SECRET) instead of re-using MCP API keys.
  2. Consider sharding session memory or using time-to-live policies to bound FAISS size.
  3. For production, run FAISS on a Linux host with available wheels (faiss-cpu) or use a managed vector DB.
  4. Secure communication between services (TLS) and enforce API rate limits on external APIs (OpenAI/Anthropic/MCP).
